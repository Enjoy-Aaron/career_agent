## 二、逐环节脚本

### ① 发现了什么真实职业规划问题？（40 秒）

> **一句话痛点**：大学生不是不努力，而是"**不知道该往哪个方向努力**"。同一个专业，有人大一就开始刷算法，有人大三才发现自己学的课和招聘要求对不上。

- 两个具体问题（对应方向 A）：
  1. 不知道**大学各个阶段该学什么**；
  2. 不知道**所学课程与就业市场有什么联系**。
- 数据佐证（真实数据 10 分点）：我们从公开招聘平台摘录了后端、AI 两个方向共 8 条真实招聘，发现同一岗位族里"Spring Boot、MySQL、Redis"反复出现，而这些和课表上的课程存在明显错位。

---

### ② Agent 如何获取信息、处理任务、提供帮助？（80 秒）

用一张流程图（或口头）讲清 5 步闭环：

1. **获取**：真实招聘文本 → 提取技术栈、学历、经验、通用能力（硬性/加分分开）；
2. **归一**：别名归一到标准词表，同义去重，按"去重招聘数"统计频次；
3. **映射**：能力缺口 → 本专业课程 / 课外项目 / 竞赛 / 实习（带先修、工时、验收标准）；
4. **排程**：按年级 + 技术基础 + 每周时间，生成分学期路线图 + 未来四周任务；
5. **调整**：改目标岗位或时间条件，自动重规划，输出"新增/保留/延期/移除"版本差异。

**必讲的一个设计决策（25 分技术分的核心）**：
> 模型只负责"理解"，**归一、计数、工时、先修依赖、计划校验全部由程序确定性计算**——模型无法绕过规则编造计划。

顺带点出安全边界：工具白名单、参数校验、8 步上限、提示注入防护、原子落盘。

### ③ 现场演示（210 秒，最核心）

**准备**：提前用 `start_lan.bat` 启动局域网模式（若现场无 WiFi，用本机 `start.bat` + 投影即可），走到"已建档 + 已分析"状态。

**演示 A：一个完整任务（约 90 秒）**

1. 建画像：选专业、学期、目标岗位族、每周时间、路径；
2. 点"分析招聘"→ 展示**技能频次图**（硬性 vs 加分双色条形）+ **能力结构环形图**；
3. 点"生成路线"→ 展示**能力差距雷达图** + **分学期路线时间轴** + **工作量堆叠图**；
4. 点"导出报告"→ 展示含"职业规划思考"章节的完整报告。

**演示 B：一次条件改动（约 120 秒，评分标准"动态改进"的体现）**

- 改动一：**切换目标岗位**（后端 → AI），展示缺口如何变化、路线如何重排；
- 改动二：**切换路径**（就业 → 考研），展示"考研固定复习块"如何挤占时间、哪些项目被延期；
- 强调：**版本差异**（新增/保留/延期/移除）+ **已完成成果永不丢失**。

> 这两个改动正好直接回答方向 A 的思考题："就业、考研等不同路径会怎样改变我的时间分配？"

---

### ④ 对自身职业方向的新认识（60 秒）

挑 2–3 个"只有自己跑过才有的体会"（真实、不套话）：

- 以前以为"会 Java 就能做后端"，跑完发现**后端真正的硬门槛是一套组合拳**（语言 + 数据库 + 中间件 + 工程化），单点技能没有竞争力；
- 学历门槛是**分岗位族的**：AI 岗普遍要硕士，后端岗本科友好——这直接影响我"考研还是就业"的决策，Agent 把这件事量化了；
- 明白了"**硬性 vs 加分**"的差别：很多同学把时间花在加分项上，却漏了硬门槛。

---

### ⑤ Agent 有哪些不足，哪些决策必须自己做？（60 秒）

用 `docs/agent-limitations.md` 的内容，讲两点：

1. **不足**：数据是静态快照、排程是启发式而非最优解、软技能无法客观测量；
2. **必须自己做**：选哪个岗位、就业还是考研、优先学什么——这些是**价值判断**，Agent 刻意留白。

**收尾金句**：
> 这个 Agent 能告诉你"路在哪里、每条路要付出什么"，但"走哪条路"，永远是你自己的选择。计算归 Agent，判断归学生——这才是"属于大学生自己的"职业发展 Agent。

## 三、可能被问到的刁钻问题（准备）

| 问题 | 参考答案要点 |
|---|---|
| 8 条招聘数据够吗？会不会过时？ | 够用于课程作业的"方法验证"；已保留批量导入 + URL 抓取接口，可随时扩充；数据来源与获取日期全部留痕 |
| 为什么不用现成的职业规划大模型？ | 现成模型给不出"可验证的分学期路线"；本项目把计算程序化，结果可复现、可校验 |
| 排程结果是最优的吗？ | 不是，是"启发式可行解"；这是诚实的取舍，详见不足清单 |
| 模型会不会乱来？ | 工具白名单 + schema 校验 + 计划必须过程序校验，模型无法绕过规则 |
| 为什么本地模型这么慢？ | 已用确定性路由缓解；云端模式已接好，需要时可切换 |
