# 架构与设计说明

本文档补充 `README.md`，深入说明本项目的架构分层、数据流与关键算法，供答辩与技术评审参考。

## 一、端到端数据流

```
[真实招聘文本]
      │  ① 提取（model_adapter.extract_job）
      │     模型/规则输出候选命中 + 原文证据（quote）
      ▼
[归一化] 别名 → canonical_id，同条招聘去重，硬性优先于加分
      │  ② 聚合（planner.aggregate_analysis）
      ▼
[按岗位族聚合] 按"去重招聘数"统计 required_count / bonus_count / 频率
      │  ③ 差距（planner.gap_analysis）
      ▼
[能力差距] 已掌握 / 待评估 / 硬性缺口 / 加分缺口 / 学历提示
      │  ④ 匹配（tools.match_activities）
      ▼
[缺口 → 活动] 课程(证据) + 项目/竞赛/实习(先修+工时+交付物+验收)
      │  ⑤ 排程（planner.build_plan）
      ▼
[分学期路线] 先修拓扑 + 工时预算 + 学期窗口 + 暑期实习块
      │  ⑥ 校验（planner.validate_plan）
      ▼
[可采纳版本] 通过预算/先修/窗口/去重四项校验才保存
      │  ⑦ 调整（tools.adjust_conditions）
      ▼
[版本差异] 新增/保留/延期/移除 + 影响说明，已完成成果不丢失
```

## 二、模块职责边界

| 模块 | 只做 | 不做 |
|---|---|---|
| `model_adapter.py` | 理解招聘文本，输出候选命中与证据 | 不做计数、排程、校验 |
| `planner.py` | 确定性规则计算（聚合/差距/排程/校验/差异） | 不调用模型、不读外部数据 |
| `tools.py` | 工具白名单、参数校验、业务编排、报告渲染 | 不做底层 HTTP、不做持久化 |
| `agent.py` | 工具调用循环、意图路由、调用上限、记录 | 不做具体业务计算 |
| `storage.py` | JSON 原子落盘、读取 | 不懂业务 |
| `schema.py` | 结构化校验 | 不执行业务 |
| `app.py` | HTTP 路由、静态资源、请求解析 | 不做业务逻辑 |

这种"理解与计算分离"的边界，保证模型只能影响"理解"这一步，后续所有可验证结论都由可测试的纯函数产出。

## 三、关键算法

### 1. 技能归一与聚合

- **别名归一**：英文别名走词边界正则（避免 `Go` 误匹配 `Google`），中文走子串匹配；`canonical_id` 是唯一主键。
- **去重统计**：同一 `job_id` 只计一次（转载/重复岗位去重），同一招聘内同一技能只计一次，硬性要求优先于加分。
- **频率**：`required_freq` / `bonus_freq` / `mention_freq` 均 = 计数 / 该族去重招聘数。

### 2. 核心硬门槛判定

```
core_threshold = ceil(job_count * 0.6)
核心技能 = { 硬性出现次数 >= core_threshold 的技能 }
```

只把"大多数招聘都硬性要求"的技能当核心，避免长尾技能干扰优先级。

### 3. 学期排程（贪心 + 拓扑）

1. 候选活动 = 本族/both、未完成、覆盖缺口、仍含未掌握技能；
2. 递归拉入先修活动；
3. 排序优先级：**技术核心 > 拓扑层级 > 通用能力核心 > 长尾价值 > 工时**；
4. 按学期贪心装填：先修满足 + 窗口匹配 + 预算足够才放入；
5. 实习走暑期块独立安排，考研/保研为固定块优先占用预算。

### 4. 计划校验（不通过不可采纳）

- **预算**：每学期总工时不超预算；
- **先修**：每个活动的先修技能在前序已满足；
- **窗口**：活动安排在 `semester_window` 内；
- **去重**：普通活动不重复（固定块允许跨学期）。

## 四、安全与鲁棒性

- 工具白名单 + 参数 schema 校验 + 8 步调用上限；
- 系统提示词固定，资料文字无法注入指令；
- 不执行模型生成的代码；
- 原子写入，重启可恢复；
- 模型失败降级为可理解的错误，不伪装结果。
