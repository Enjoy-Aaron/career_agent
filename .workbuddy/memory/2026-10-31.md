# 2026-10-31 工作日志

## 修复：本地模型模式下对话"无回应"

**根因**：qwen2.5:3b 在无独显机器上 CPU 推理，做工具调用一次往返 40 秒+，且前端无加载提示，用户发消息后界面空白，误以为卡死/无回应。

**改动**：
1. `core/agent.py` — chat 循环加确定性路由兜底：本地/云端模式下，首条消息命中明确指令（_INTENT_RULES）时走规则路由，跳过模型多轮工具调用往返；未命中才交给模型。`_route_by_rules` 收尾返回空字符串，`_mock_summary` 区分 mock/local 措辞。
2. `core/model_adapter.py` — 新增 `extract_mode` 配置：local 模式默认 rule（规则提取招聘技能，快且稳），cloud 默认 model。`extract_job` 据此分支，避免 analyze_jobs 逐条调慢模型卡死。
3. `web/app.js` — sendChat 加"Agent 正在思考…"占位气泡 + 发送按钮禁用，收到回复后移除。
4. `web/styles.css` — 加 .msg-agent.thinking 动画样式。
5. `config.json` / `config.example.json` — 加 extract_mode=rule 及说明。
6. `scripts/acceptance_test.py` — 场景0 断言从"默认 mock"改为"模式正确上报"（兼容 mock/local/cloud）。

**验证**：验收 32 PASS / 0 FAIL；实测 分析招聘 0.10s、对话指令 0.19s、导出报告 0.36s（修复前 40s+）。

## 局域网共享（答辩演示）
- 需求：让同一 WiFi 下评委/同学访问。
- 改动：`app.py` 加 `HOST = env CAREER_HOST 默认 127.0.0.1`；新增 `_print_lan_urls()` 打印局域网地址；新增 `start_lan.bat`（设 CAREER_HOST=0.0.0.0 启动）。
- 架构事实：调用模型的是后端 app.py 进程，访问者浏览器只连 8000，后端内部连 127.0.0.1:11434 的 Ollama，故 **Ollama 无需改监听地址**。
- 验证：0.0.0.0:8000 绑定成功，经局域网 IP 172.22.49.147 走完整对话通，1.5B 闲聊 8.4s。
- 注意：用户已自行把模型换成 qwen2.5:1.5b（config.json 仍写 3b，实际 Ollama 里是 1.5b，两者不一致需提醒）。
