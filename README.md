# 岗位需求反推成长规划 Agent

> **AI 赋能职业成长：设计属于大学生自己的职业发展 Agent** · 方向 A：岗位需求反推大学四年成长规划

一个"从真实招聘信息出发，反推大学四年成长路线"的本地职业规划 Agent。它回答一个大学生最焦虑、又最难自己搞清的问题：

**大学各个阶段到底该学什么？我学的这些课，和招聘市场到底有什么关系？**

---

## 一、它解决了什么问题

| 痛点 | 本项目的回答 |
|---|---|
| 不知道各阶段该学什么 | 从真实招聘提取能力要求，反推"分学期成长路线图" |
| 不知道课程与就业的联系 | 把岗位能力映射到本专业课程、课外项目、竞赛、实习 |
| 不知道哪些是硬门槛、哪些是加分 | 硬性要求与加分项**分开统计**，频次只作优先级参考、不等于硬门槛 |
| 不知道就业 / 考研 / 保研怎么取舍 | 三种路径分别排程，改变路径自动重规划并给出时间分配差异 |
| 计划一变就全乱 | 版本化管理 + 差异对比，已完成成果与可迁移能力**永不丢失** |

---

## 二、核心功能（对应题目 5 条）

1. **招聘要求提取** — 从真实招聘文本提取技能、学历、经验、通用能力，同义词归一、去重、按"去重招聘数"统计频次。
2. **技能归类合并** — 别名统一到标准词表（`skill_taxonomy.json`），识别重复出现的核心要求，硬性/加分分离。
3. **能力-资源对应** — 把能力缺口映射到本专业课程（`courses.json`）、课外项目/竞赛/实习（`activities.json`），给出先修、工时、交付物与验收标准。
4. **分学期路线生成** — 根据年级、技术基础、每周可投入时间，生成剩余学期路线 + 未来四周可执行任务。
5. **动态调整** — 改变目标岗位 / 每周时间 / 发展路径时自动重规划，输出"新增 / 保留 / 延期 / 移除"版本差异。

## 三、架构分层

```
web/               前端（原生 JS + CSS + HTML，零依赖）
  └─ 画像 / 岗位分析 / 成长路线 / 反馈调整 / Agent 对话 / 报告导出
app.py             HTTP 入口（标准库 http.server，单用户本地运行）
core/
  ├─ agent.py      主 Agent：工具调用循环、意图路由、调用上限、运行记录
  ├─ tools.py      业务工具白名单：10 个工具的 schema + 实现 + 分发
  ├─ planner.py    规则引擎：聚合、差距、排程、校验、版本差异（确定性计算）
  ├─ model_adapter.py  模型适配层：mock / local / cloud 三模式，别名归一
  ├─ schema.py     零依赖结构化校验（替代 pydantic 的最小实现）
  └─ storage.py    JSON 原子落盘持久化
data/              真实招聘样本、标准词表、课程库、活动库（静态知识）
state/             运行状态（画像、分析、计划版本、完成记录、日志）
scripts/           验收测试与调试工具
```

## 四、关键设计决策（"深度思考"的核心）

### 1. 模型只负责"理解"，可验证计算全部由程序完成

这是本项目最重要的架构选择。招聘提取里大模型只输出"候选命中 + 原文证据"，**归一、去重、计数、工时、先修依赖、版本差异全部由 `planner.py` 确定性计算**。好处：

- 模型（无论 mock 还是真实模型）都无法绕过规则——同一个归一函数，结果可复现、可校验；
- 计划必须通过"预算 / 先修 / 窗口 / 去重"四项程序校验才会被保存为可采用版本，**绝不让模型编造一个"看起来合理但实际冲突"的计划**。

### 2. 频次 ≠ 门槛，硬性 ≠ 加分

技能按"去重招聘数"统计，硬性要求与加分项**分开计数**。频次只用于排序优先级，明确标注"不等于硬门槛"；只有出现在 60% 以上招聘中的硬性技能才进入"核心硬门槛"，长尾技能不喧宾夺主。每个结论都挂原文引用与来源链接。

### 3. 安全边界（不是空话，是代码）

- **工具白名单**：模型只能调用登记在 `TOOL_SPECS` 里的工具，参数先过 schema 校验再执行；
- **调用上限**：单轮最多 8 步，防止无限循环；
- **提示注入防护**：系统提示词固定，招聘资料只作为数据字段传入，资料文字无法改变系统规则；
- **不执行模型生成的代码**；
- **原子落盘**：临时文件 + `os.replace`，重启可完整恢复，中途断电不产生半截文件。

### 4. 三档模型模式，零依赖可离线演示

- **mock（默认）**：纯规则实现，确定性、可复现，无需网络与密钥，开箱即完整演示；
- **local**：对接 Ollama 等本地 `/v1/chat/completions` 服务；
- **cloud**：对接任意 OpenAI 兼容接口，密钥仅存本地 `config.json`。

模型失败会抛出 `ModelError` 给出可理解的错误，**绝不把模拟结果伪装成真实模型结果**。

## 五、快速启动

```bash
# 方式一：双击 start.bat（Windows）
# 方式二：命令行
python app.py
# 浏览器自动打开 http://127.0.0.1:8000
```

默认模拟模式，无需任何密钥即可完整演示。需要真实模型时，复制 `config.example.json` 为 `config.json` 并修改 `mode` / `base_url` / `api_key`。

## 六、验收方式

```bash
python app.py --no-browser      # 先启动服务
python scripts/acceptance_test.py   # 另开终端运行
```

覆盖 6 大验收场景共 **32 项断言**（分析、差距、排程、动态调整、持久化、异常边界），全部通过即视为可用。

## 八、数据说明

- 招聘样本来自公开招聘平台（牛客、国家大学生就业服务平台、各校就业网、企业官网等），**均保留原文、来源链接与获取日期**，仅用于课程作业分析，不做自动批量抓取；
- 课程库依据**华南农业大学计算机科学与技术专业培养方案与执行计划**整理，课内课程作为"能力证据"，不占用课外工时预算；
- 活动库（竞赛/实习/项目）依据教育部公开竞赛名单与真实招聘要求整理，具体机会须按当期公告核实。
